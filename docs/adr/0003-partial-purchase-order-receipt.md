# Partial Purchase Order Receipt & Issue Resolution

เราต้องการรองรับกรณีที่ร้านค้าส่งสินค้าไม่ครบตามใบสั่งซื้อ (PO) โดยไม่แก้ไขตัวเลขสั่งซื้อเดิมย้อนหลัง และตัดสต็อกพร้อมบันทึกรายจ่ายเฉพาะสินค้าที่ได้รับจริงในแต่ละรอบ

## Considered Options

- **แก้จำนวนใน PO เดิมให้เท่ากับของที่ได้จริง** — ง่าย แต่สูญเสีย Audit Trail ไม่รู้ว่าเดิมสั่งเท่าไหร่ และทวงของที่ขาดไม่ได้
- **บังคับรับของครบเท่านั้น (All-or-Nothing)** — ไม่ตรงกับความจริงในการทำธุรกิจ ร้านค้ามักส่งของขาดและทยอยส่งเพิ่ม
- **เพิ่มสถานะ `PARTIALLY_RECEIVED` + ตารางติดตามปัญหา (`purchase_order_issues`)** ✅ — สต็อกและรายจ่ายเพิ่มตามจริง มีตารางเตือนของขาด และรองรับทั้งการรับของเพิ่มรอบสอง หรือการยุติปัญหาด้วยส่วนลด/คืนเงิน

## Consequences

- `purchase_order_status` เพิ่มค่า `PARTIALLY_RECEIVED`
- ตาราง `purchase_order_items` เพิ่มคอลัมน์ `receivedQuantity` สำหรับนับจำนวนที่รับแล้วสะสม
- ตาราง `purchase_order_issues` เก็บรายการสินค้าที่ขาด, จำนวนที่ขาด, สถานะ (`OPEN` / `RESOLVED`), ประเภทข้อยุติ และบันทึกหมายเหตุ
- รายจ่ายการเงิน (Expense Transaction) จะถูกบันทึกแบบ Incremental เฉพาะมูลค่าสินค้าที่รับจริงในรอบนั้นๆ
- PO จะเปลี่ยนสถานะเป็น `RECEIVED` ได้สองทาง: เมื่อได้รับของที่ขาดครบทั้งหมด หรือเมื่อพนักงานกดยุติปัญหา (เช่น ได้รับส่วนลดรอบหน้า)
